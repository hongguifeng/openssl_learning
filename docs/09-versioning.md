# 第 9 章：版本演进与迁移

| 版本 | 重点变化 | 迁移关注 |
| --- | --- | --- |
| 1.0.2 | 结构体大量公开、ENGINE 生态 | 不要把结构体字段访问带入新代码 |
| 1.1.0/1.1.1 | 结构体 opaque、自动初始化、TLS 1.3（1.1.1） | 线程/初始化假设和 TLS 行为变化 |
| 3.0+ | Provider、fetch、参数 API、FIPS provider | EVP 化、属性查询、弃用警告 |

迁移策略：打开弃用警告，先替换低级摘要/加密/签名接口，再处理 ENGINE 到 provider 的边界，最后在目标 OpenSSL 版本矩阵上跑互操作测试。不要只依赖 `OPENSSL_VERSION_NUMBER` 做复杂行为分支；优先检测能力和返回值。

仓库提供一个简单的迁移门禁：

```sh
./scripts/check_modern_api.sh
```

它扫描实验代码中的典型 ENGINE/低级算法符号；真实项目还应打开弃用警告并进行跨版本构建。
