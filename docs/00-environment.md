# 第 0 章：先建立正确的学习地图

这一章的目标不是背 API，而是回答三个问题：

1. 我到底要解决哪一种安全问题？
2. OpenSSL 的哪一层负责解决它？
3. 在嵌入式设备上，哪些条件不满足时，调用 API 也不会得到安全结果？

如果这三个问题没有答案，直接复制一段 AES 或 TLS 代码，通常只会得到“能运行但不一定安全”的程序。

## 0.1 OpenSSL 是什么，不是什么

OpenSSL 是一组 C 库和命令行工具。它主要包含两条主线：

```text
libcrypto                         libssl
密码原语和对象管理                TLS 协议和记录层
│                                 │
├─ EVP：摘要、AEAD、签名、KDF     ├─ SSL_CTX：一类连接的配置
├─ X.509/ASN.1：证书和编码         ├─ SSL：一次具体连接
├─ RAND：随机数                    ├─ BIO/socket：I/O
└─ Provider：算法实现             └─ X.509 验证：对端身份
```

OpenSSL **不会**替你完成以下产品决策：

- 设备私钥放在哪里、谁可以使用；
- 设备是否有可信时间；
- 证书应该信任哪些 CA；
- GCM nonce 如何持久化、断电后如何避免重复；
- 连接失败后是否重试、重试多久、是否进入安全故障状态。

这些属于系统设计和威胁建模，后面的 STM32/FreeRTOS 章节会把它们具体化。

## 0.2 用“安全属性”选择组件

| 想保护什么 | 适合的组件 | 不能误解成什么 |
| --- | --- | --- |
| 防止传输内容被窃听并检测篡改 | TLS 1.3 或 AES-GCM/ChaCha20-Poly1305 | 只调用 SHA-256 |
| 证明消息来自持有私钥的一方 | ECDSA/Ed25519 签名，或 TLS 证书 | 只做 Base64 |
| 从口令派生密钥 | PBKDF2/scrypt/Argon2（支持范围需核对） | 直接 `SHA256(password)` |
| 从共享秘密产生多个会话密钥 | HKDF | 直接截取 ECDH 输出 |
| 验证服务器身份 | X.509 链 + SAN/主机名 + 用途检查 | “证书能解析” |
| 生成不可预测密钥/nonce | 操作系统 RNG、STM32 TRNG、安全芯片 | `rand()` 或固定种子 |

一个常见误区是把“哈希”当作“加密”。哈希是把任意长度输入映射为固定长度摘要；它通常不可逆，但没有密钥，也就不能单独证明消息来源。HMAC 是带密钥的摘要，数字签名则使用私钥/公钥体系。

## 0.3 你会在代码里遇到的四类对象

OpenSSL 3.x 的 API 之所以看起来复杂，是因为它把一次操作拆成了几个生命周期不同的对象：

1. **算法描述对象**：例如 `EVP_MD` 表示“某个摘要算法”；它通常由库管理，应用只拿指针使用。
2. **操作上下文**：例如 `EVP_MD_CTX` 表示“一次正在进行的 SHA-256 计算”；它必须由应用创建和释放。
3. **密钥对象**：`EVP_PKEY` 表示一把公钥/私钥，但不暴露 RSA/EC 结构体字段。
4. **配置/连接对象**：`SSL_CTX` 是一类 TLS 连接的共同配置，`SSL` 是一次具体连接。

学习每个 API 时都问四件事：

```text
谁创建？谁拥有？什么时候初始化？失败时由谁释放？
```

## 0.5 学习检查点

1. 为什么“SHA-256 摘要正确”不能证明消息来自服务器？
2. 为什么 TLS 连接既会用到 `libssl`，也会用到 `libcrypto`？
3. `SSL_CTX` 和 `SSL` 为什么要分成两个对象？
4. STM32 没有可信时间时，证书有效期检查会遇到什么问题？
