# 第 0 章：环境与密码学边界

## 学习目标

本章不重复讲 C 语法，而是建立后续实验需要的边界：OpenSSL 是密码学和安全通信工具箱，不是一个自动替你完成威胁建模的“加密按钮”。

| 问题 | 常用原语/组件 | 关键属性 |
| --- | --- | --- |
| 防止内容被窃听 | AES-GCM、ChaCha20-Poly1305 | 机密性 + 完整性 |
| 判断消息来自谁 | HMAC、数字签名、证书 | 身份认证 |
| 安全地产生共享密钥 | ECDH、HKDF | 密钥协商/派生 |
| 判断数据是否被改动 | SHA-256、SHA-3 | 摘要，不提供认证 |
| 建立网络安全连接 | TLS 1.3、X.509 PKI | 协议、身份、密钥生命周期 |

### 先建立三个判断

1. **哈希不是加密**：知道摘要不能还原原文，但单独使用摘要不能证明消息来自可信设备。
2. **加密不等于认证**：优先使用 AEAD（如 AES-GCM），不要自行拼接“加密 + 哈希”。
3. **证书验证是策略**：链能构建成功，不代表主机名、用途、时间和信任根都符合产品策略。

## 实验：记录环境基线

在仓库根目录执行：

```sh
./scripts/check_env.sh
```

脚本会同时打印命令行工具版本和头文件/运行时版本，并编译一个只依赖 `libcrypto` 的探针。这里的版本信息要保存到你的学习记录中，因为 OpenSSL 3.x 的 provider、配置目录和算法属性会随发行版变化。

## STM32/FreeRTOS 预告

在 MCU 上，最需要提前确认的不是 API 名称，而是四个平台条件：

- 是否有可信熵源（TRNG 或安全协处理器）；
- 网络栈是否提供可靠的 socket/非阻塞语义；
- 任务并发、堆分配和栈大小是否足以承载 TLS 握手；
- 设备时间是否可信，能否正确验证证书有效期。
