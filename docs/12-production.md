# 第 12 章：生产安全——把示例变成可维护的设备功能

教程结束不等于产品安全完成。生产系统需要把密钥、证书、升级、故障和审计放进一个可恢复的生命周期。

## 12.1 设备安全通信的状态机

```text
BOOT
  │ RNG/时间/证书存储自检成功
  ▼
READY ──网络可用──> CONNECTING ──TLS 验证成功──> ESTABLISHED
  ▲                    │                         │
  │                    └─超时/证书错误───────────┘
  └────安全故障/退避 <────重试策略/轮换证书───────
```

每个状态都要定义：允许发送什么、保存什么、重试多少次、日志记录什么、如何从断电恢复。证书错误不能无限重试；随机数故障更不能通过重启循环掩盖。

## 12.2 密钥生命周期

```text
生成/注入 → 激活 → 使用 → 轮换 → 吊销/失效 → 安全销毁
```

需要回答：

- 私钥在哪个边界生成，是否曾以明文离开安全芯片？
- 设备制造、首次启动、OTA 更新分别使用什么身份？
- 证书轮换失败时旧证书还能否安全使用？
- 设备时钟回退会不会导致 nonce/证书策略回退？
- 崩溃转储、日志和调试口会不会泄露密钥？

## 12.3 生产配置检查

- 默认启用 TLS 证书链、主机名、用途和时间校验；
- 明确协议版本、密码套件和 ALPN；
- 禁止把 `SSL_VERIFY_NONE`、固定测试 key、玩具 provider 带入生产构建；
- 私钥使用安全存储或硬件 key handle；
- 对 RNG、证书、provider、网络和内存失败定义故障状态；
- 跟踪 OpenSSL 安全公告、发行版补丁和 FIPS 配置；
- 发布前固定依赖版本、编译选项、provider 模块和配置文件。

## 12.4 实验：发布前自审

```sh
./scripts/verify_tutorial.sh
rg -n 'SSL_VERIFY_NONE|EVP_MD_fetch|OSSL_PROVIDER_load' .
```

对每个 `SSL_VERIFY_NONE` 逐处说明它是否仅存在于测试代码；对每个 provider/fetch 调用记录算法属性、配置来源和失败处理。再为目标设备执行证书轮换、错误主机名、断电恢复、RNG 不可用和网络抖动测试。

## 12.5 建议形成的交付文档

1. 威胁模型：资产、攻击者能力、信任边界；
2. 密钥生命周期和证书轮换方案；
3. OpenSSL 版本/provider/FIPS 配置清单；
4. 资源预算：Flash、RAM、堆、栈、CPU、功耗；
5. 测试报告：成功、失败、故障注入、互操作和真实设备；
6. 安全响应：CVE 评估、补丁、回滚和设备吊销。

## 12.6 最终学习检查点

如果你能清楚回答下面问题，才算从“会调用 API”进入“能负责模块”：

- 设备如何证明服务器身份？
- 私钥如何生成、保存、使用和轮换？
- RNG/时间/网络/内存任一依赖失败时，系统进入什么状态？
- 你的 provider/FIPS 边界在哪里，如何证明算法来自正确实现？
- TLS 连接如何在 FreeRTOS 任务中处理超时、短读写和重连？
